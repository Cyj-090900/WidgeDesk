# GlassDesk 4.1.2

**修复：从搜索结果加入启动台的应用被误判为「目标已不在原处」。**

症状是磁贴上一直挂着 ⚠，底部提示「目标已不在原处，请重新定位：
shell:AppsFolder\...」，点它还会拒绝启动。

## 原因

从搜索结果加入的应用，目标是 `shell:AppsFolder\<AUMID>` —— 这是交给外壳解析的
标识，**不是磁盘上的文件路径**。而判断「目标还在不在」的那处代码只豁免了网址，
其余一律用 `File.Exists` 检查，`shell:` 目标必然为假，于是被标成失效。

加入的当下不显示 ⚠（标记初始为假），但**下次启动**的例行复查会把它标上，
所以看起来是「老是出现」。

## 修法

判断目标存在性时豁免 `shell:` 形式的目标：这类目标能不能打开只有外壳知道，
在这里用文件存在性去推断只会得出错误结论，交给启动去撞真实结果。

真正不存在的**文件路径**目标仍然照旧标为失效——豁免只覆盖 `shell:` 前缀，
不会把「目标真的没了」一起放过。

## 已经中标的条目会自动恢复

升级后第一次启动时，例行复查会把这些条目重新判为正常并清掉 ⚠、写回磁盘，
不需要手动「重新定位」。

功能与 4.1.1 相同，只有这一处修复。
