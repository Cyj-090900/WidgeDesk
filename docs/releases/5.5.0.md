# WidgeDesk 5.5.0

## 点击网络/时钟：唤出**真正的**操作中心

上一版我说过"系统浮层搬不动"，那个结论是错的——我只枚举了顶层窗口，
而且用错了输入方式。这次实测把路走通了：

| 尝试 | 结果 |
|---|---|
| 向 `TrayButton` 发 `WM_LBUTTONDOWN/UP`、`BM_CLICK` | 无反应 |
| `SetCursorPos` + `mouse_event` 点击任务栏那颗按钮 | 无反应 |
| **`SendInput` 发送 Win+A** | **操作中心真的弹出**（已截图确认：定位 / WLAN / 蓝牙 / 夜间模式 / 所有设置 / 音量滑杆 全部在） |

所以现在 Dock 托盘区的**网络图标与时钟**点击后，会唤出 Windows 原生操作中心，
和你在任务栏上按 Win+A 的效果完全一致。系统不接受这条路径时才退回网络/时间设置页。

## 后台应用也会出现在 Dock 上

你截图里那些通知区小图标（WPS、飞书、Telegram、Spotify、OneDrive 之类）
以前不会出现在 Dock 上——因为 Dock 只枚举**顶层窗口**，而它们平时把窗口收进通知区，
根本没有顶层窗口。

现在补上了这条来源：

- 读取任务栏通知区 `ToolbarWindow32` 的每个按钮，跨进程取回 `TRAYDATA`，
  得到「哪一枚图标属于哪个进程」。
- 按进程去重，取映像的「文件说明」作为名称，图标走与其它磁贴相同的提取路径。
- 出现在应用图标之后、托盘区之前，带运行状态点；点击即启动或激活该应用。

实测结果：本机读取到「WPS 服务程序」「Feishu」两条，并自动生成了对应磁贴。

### 去重与排除

- 已固定在 Dock 上的、或窗口类自动磁贴已经覆盖的，不会重复出现。
- 用户从 Dock 上移除过的（`SuppressedAutoItemIds`），不会自己回来。
- `ApplicationFrameHost` / `RuntimeBroker` / `ShellExperienceHost` / `SearchApp` /
  `TextInputHost` 这类纯宿主进程不上 Dock——它们本身不是用户会启动的程序。
