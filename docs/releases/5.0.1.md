# WidgeDesk 5.0.1

**修复：「检查更新」报 403 限流时，界面只显示一句英文原文。**

## 问题

点「检查更新」，界面出现：

> 无法检查更新，请确认网络连接后重试。
> Response status code does not indicate success: 403 (rate limit exceeded).

这句话有两个毛病：它把 GitHub 的内部错误原样抛给用户，既看不懂；而且它说
「请确认网络连接」，但**网络是好的**——真正的原因是请求次数用完了。

## 原因

GitHub 对**匿名** API 请求按来源 IP 限流，每小时 60 次。程序检查更新时没有令牌，
所以受这个限制。共用出口的地方（公司、校园网、运营商 NAT）尤其容易撞上——
额度是整个出口共享的，不是每台机器各 60 次。

## 修法

- 识别出限流，给一条能照做的说明：还剩多少额度、什么时候恢复、这不是网络故障。
- 记住恢复时间：**在此之前不再自动检查**。否则每开一次程序就撞一次，
  把一个本来会自己恢复的短时限流，拖成看起来「一直坏着」。
- 手动检查不受这个限制——用户主动点了，就该给他真实答案。
- 普通的 403（真的没权限）仍按原样报错，不会被误说成「请求太频繁」。

## 说明

这不是永久故障。额度每小时恢复一次，到点后「检查更新」会自动恢复正常。

功能与 5.0.0 相同，只有这一处修复。
