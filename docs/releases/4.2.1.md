# GlassDesk 4.2.1

**修复：点 Dock 上已经开着的应用，会再开一个。**

## 问题

应用（例如答疑工作台）已经在运行，在 Dock 上点它的图标，结果**又多开了一个**，
而不是把已有的窗口切到前面。这与 Windows 任务栏的行为不一致——点任务栏图标
永远是「切过去」，不是「再开一个」。

## 原因

自动出现的图标只因为「这个应用有窗口」才存在，点它的时候窗口一定在那里。
但点击路径在「应用不在应用库」的情况下**直接去启动**，完全没有用上它手里
握着的窗口句柄——于是多开一个就成了必然结果。

多数程序不会自己判断「我已经开着了吗」，所以把「切过去」的职责丢给应用自己，
就是把这个缺陷留给了用户。

## 修法

点击自动图标时先看它记下的窗口：

- **有一个窗口** → 直接切到前面。
- **有多个窗口** → 弹出让用户选（与任务栏点分组图标一致）。
- **一个都没有** → 这才轮到启动，那是「应用刚退出、状态还没刷新」的兜底。

只要还有窗口，就绝不启动新实例。这条规则现在是一个可单测的判定，
不是散落在点击处理里的一段 if。

## 顺带修的一处

固定图标点击时原本会**重新枚举一次窗口**，而状态点依据的是上一次刷新的结果。
两者可能对不上，表现是「小圆点亮着，点它却新开一个」。现在点击复用同一份快照；
万一快照比现场旧，启动之前会再按现场确认一次——宁可多查一遍，也不多开一个。

## 已知行为

切换窗口失败时（系统拒绝前置）会如实提示，**不会**偷偷退回去启动一个——
那样只会让「多开」这个缺陷以另一种形式出现。
